**`@dudousxd/nestjs-authz`** builds on NestJS's first-party
[`@nestjs/authorization`](https://docs.nestjs.com/security/authorization). Policies (`@Policy()`),
route checks (`@Can(Policy, 'ability', args?)`, `Can.Anyone()`), the global deny-by-default
`AuthorizationGuard`, the current user (`getUser`) and `AuthorizationService` all come from the
official package: read its docs first. This package adds only what the official one lacks:

- **Persisted RBAC as official policies**: `RolePolicy` and `PermissionPolicy` (wildcards,
  tenant-scoped roles, direct permissions, role sources), backed by the TypeORM / MikroORM /
  Prisma / Drizzle adapters and fetched once per request.
- **Helpers for the official `@Can()`**: `byId(Post)`, `roles(...)`, `permission(...)`,
  `ability(...)`, `staticCanArgs(...)`; sugar `@Roles(...)` / `@Permission(...)`.
- **A global super-admin** and an **external policy engine** (Cerbos, OPA, …), honored by
  policies that extend `AuthzPolicy`.
- **A `Gate`** for services: string abilities, policy-class checks, batches (`allowsMany`),
  ad-hoc gates (`define`), roles, query scopes (`scope` + the adapters' `applyScope`).
- **Frontend and tooling**: Inertia props, a typed `can()` from codegen, client/React helpers,
  test helpers, and an allow + deny decision event for Telescope.

## Quickstart

<Steps>
<Step>

Install the official package and the extras:

```bash
pnpm add @nestjs/authorization @dudousxd/nestjs-authz
```

</Step>
<Step>

Import both modules:

```ts title="app.module.ts"
import { Module } from '@nestjs/common';
import { AuthorizationModule } from '@nestjs/authorization';
import { AuthzModule } from '@dudousxd/nestjs-authz';
import { PostPolicy } from './post.policy';

@Module({
  imports: [
    AuthorizationModule.forRoot(), // official: guard, @Can, AuthorizationService
    AuthzModule.forRoot({ superAdmin: (user) => user?.isRoot === true }),
  ],
  providers: [PostPolicy],
})
export class AppModule {}
```

</Step>
<Step>

Write an official policy; `@PolicyFor` links it to its resource for the extras:

```ts title="post.policy.ts"
import { Policy } from '@nestjs/authorization';
import { AuthzPolicy, PolicyFor } from '@dudousxd/nestjs-authz';

@Policy()
@PolicyFor(Post)
export class PostPolicy extends AuthzPolicy {
  update(user: User | null, post: Post) {
    return post.authorId === user?.id;
  }
}
```

</Step>
<Step>

Guard the route with the official `@Can` and our `byId` helper:

```ts title="posts.controller.ts"
@Patch(':id')
@Can(PostPolicy, 'update', byId(Post)) // loads the Post named by :id
update(@Req() req: Request) {
  const post = authorizedResource(req, Post); // the record byId loaded
}
```

A guest is answered 401, a signed-in user 403. The route user is the official `getUser`
(default `request.user`).

</Step>
</Steps>

## Authorization, not authentication

Authz answers "what may this user do?", never "who is this user?". Bring your own
authentication (`@nestjs/authentication`, Passport, a JWT guard); the official guard reads the
user it produced.

## What this package adds

1. **[Policies](/docs/authz/policies)** — official `@Policy()` classes, plus `@PolicyFor(Resource)`
   and the `AuthzPolicy` base (super-admin and the external engine in `before()`).
2. **[Gates](/docs/authz/gates)** — a service-layer `Gate` over `AuthorizationService`, with
   string abilities, ad-hoc gates, batches and query scopes.
3. **[RBAC](/docs/authz/rbac)** — persisted roles and permissions as `RolePolicy` /
   `PermissionPolicy`, through an opt-in ORM adapter. The core stays zero-DB.

## Migrating from 0.x

0.x had its own engine. 1.0 runs on `@nestjs/authorization`:

| 0.x | 1.0 |
| --- | --- |
| `@Policy(Post)` | `@Policy()` from `@nestjs/authorization` + `@PolicyFor(Post)` (the old form is deprecated) |
| `@Can('update', Post)` | `@Can(PostPolicy, 'update', byId(Post))` (the old form is deprecated) |
| `@Can('create', Post, { classLevel: true })` | `@Can(PostPolicy, 'create')` |
| `@Can('access-admin')` | `@Can(GatePolicy, 'allows', ability('access-admin'))` |
| `@Roles('admin')` + `RolesGuard` | `@Roles('admin')`, enforced by the official guard |
| `CanGuard`, `RolesGuard`, `PolicyRegistry` | removed: the official `AuthorizationGuard`; `PolicyIndex` |
| `AuthzModule.forRoot({ policies })` | register policies as providers (or `AuthorizationModule.forRoot({ policies })`) |
| `superAdmin` applied everywhere | applied by `AuthzPolicy` subclasses, the built-in policies and the `Gate` |
| `after` hook, `{ allowed, message }` results | removed: only a literal `true` allows |
| current user from nestjs-context on routes | the official `getUser` (default `request.user`) |
| `gate.allows()` user from nestjs-context | `AuthenticationContext.user` first, then nestjs-context |
| a persisted permission named like a policy ability grants it | the policy decides (only `superAdmin` bypasses it), in checks and in `scope()` |
| `DecisionProvider` / `superAdmin` see a guest as `undefined` | `null` |
| `DecisionProvider` asked by the Gate on every check | asked by `AuthzPolicy.before()` on routes, and by `Gate` string abilities |

The deprecated `@Can` / `@Policy` only write the official metadata, and are removed in 2.0.

<Callout type="warn" title="Behavior the official guard brings">
**Deny by default**: a handler with no `@Can()` is denied; add `@Can.Anyone()` (or `@Public()`
from `@nestjs/authentication`) where anyone may call it. **Class and method requirements add
up.** **Guests reach the policy as `null`**: type the user `User | null`; a guest denial is a 401.
</Callout>
